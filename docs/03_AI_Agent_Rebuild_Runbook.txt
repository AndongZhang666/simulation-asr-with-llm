ASR ERROR CORRECTION USING LARGE LANGUAGE MODELS
AI CODING AGENT REBUILD RUNBOOK

How to use this file
--------------------
Give this file, the paper-to-implementation specification, the architecture document, and
the original paper to the coding agent. This runbook is intentionally directive. It tells
the agent when it may proceed, what it must test, and when it must stop and report a gap.

======================================================================
1. MASTER INSTRUCTION FOR THE AGENT
======================================================================

You are rebuilding the methods described in "ASR Error Correction Using Large Language
Models" by Ma et al. Your objective is a transparent research reproduction, not a demo.
Implement the method in small, tested, reviewable increments.

Hard rules:
1. Treat the paper as the primary method source.
2. Label every implementation choice as PAPER, REFERENCE-PAPER, INFERENCE,
   RECOMMENDATION, or OPEN-GAP in the assumptions registry.
3. Never invent an unreported hyperparameter and present it as the authors' setting.
4. Never tune on a test set.
5. Never start expensive training until baseline and oracle gates pass.
6. Never overwrite raw ASR, reference, model, or API artifacts.
7. Save exact model/code/data revisions and complete resolved configs.
8. Implement corpus WER from summed edit counts and cross-check it independently.
9. Keep raw and normalized text separate.
10. Make every pipeline stage resumable and deterministic where possible.
11. Do not claim exact reproduction of the zero-shot GPT tables because the historical
    model snapshots are retired unless historical cached outputs are supplied.
12. Do not describe adjacent public projects as the authors' source code.
13. Prefer a correct, narrow implementation over a large untested codebase.
14. After each milestone, produce evidence: commands, tests, artifacts, metrics, and a
    concise gap report.

Definition of done:
- The repository can regenerate all public-data artifacts from manifests and pinned
  dependencies.
- The main supervised N-best T5 experiments run end to end.
- Unconstrained, constrained, and closest decoding are tested.
- Baseline, oracle, paper comparison, and diagnostic tables are generated automatically.
- Lattice decoding is either reproduced with tests or explicitly reported as an isolated
  unresolved module.
- A current-model zero-shot experiment is reproducible and clearly separated from the
  historical paper result.

======================================================================
2. WORKING PRACTICES
======================================================================

Repository practices
---------------------
- One milestone per branch or a short sequence of focused commits.
- Commit schemas and tests before implementation.
- No large binaries or datasets in git.
- Use type checking, linting, formatting, and unit tests in CI.
- Use dependency lock files.
- Refuse to run on a dirty git tree for official experiments unless `allow_dirty=true`
  is intentionally recorded.

Experiment practices
--------------------
- Every run ID is derived from a canonical config hash plus a human-readable prefix.
- Runs are append-only.
- A run manifest includes git SHA, dependency hash, data hashes, model revisions,
  hardware, command, start/end time, and assumptions.
- Validation selection and test evaluation are separate commands.
- Failed runs remain visible with failure metadata.

Communication practices
-----------------------
At every gate, report:
- completed tasks;
- tests passed/failed;
- produced artifact paths and hashes;
- measured values versus expected values;
- assumptions introduced;
- blocker and next action.

Goal

Tasks
-----

- Corpus WER differs correctly from average utterance WER.

Exit gate

======================================================================
6. MILESTONE M3 - WHISPER N-BEST EXTRACTION
======================================================================

Goal
----
Generate a validated 10-best artifact from a pinned Whisper small.en implementation.

Tasks
-----
1. Pin Whisper code/model revision.
2. Inspect beam-search finalization and sequence ranking.
3. Implement an adapter that returns all finalized candidates before one-best selection.
4. Save token IDs, token log probabilities when available, cumulative scores, raw text,
   and rank.
5. Disable stochastic fallback for the deterministic reproduction run.
6. Decode the CI fixture and then LibriSpeech test sets.

Required tests
--------------
- N=1 output equals the stock decoder exactly.
- Scores are descending.
- Sum of stored token log probabilities matches the cumulative score within tolerance.
- Repeated normalized candidates are retained.
- Same input/model/config gives identical output.
- No reference information enters decoding.

Analysis before exit
--------------------
- Top-1 WER on test-clean/test-other.
- Oracle WER for N=1, 5, 10.
- Raw and normalized unique counts.
- Cross-hypothesis S/D/I.
- Compare with paper's Whisper baseline 3.52/7.37 and 10-best oracle 2.14/4.73.

Decision rule
-------------
- If baseline differs by more than about 0.2 absolute WER, do not tune T5 to hide the
  difference. First inspect model revision, decoding, segmentation, and normalization.
- If the best public setup still differs, freeze it as a method-reproduction baseline and
  document the mismatch.

Exit gate
---------
- A content-addressed N-best artifact and baseline/oracle report exist.
- The Whisper patch is saved as a clean diff with tests.

8. MILESTONE M5 - N-BEST T5 DATA AND TRAINING
======================================================================

Goal
----
Train a T5-base EC model from N-best input to manual reference.

Tasks
-----
1. Implement literal `[SEP]` serialization and optional task prefix.
2. Add configurable added-token and T5-sentinel alternatives.
3. Measure source/target length distributions and truncation.
4. Build train/dev pairs from immutable ASR artifacts.
5. Implement T5 training with the paper's reported lr=5e-5, batch=32, epochs=3,
   dropout=0.1.
6. Save tokenizer and serializer fingerprint with every checkpoint.
7. Add resume and deterministic seed support.

Required tests
--------------
- Serialization order exactly follows ASR rank.
- A tiny dataset can be overfit.
- Padding is ignored in loss.
- Checkpoint resume produces equivalent continuation.
- No test examples in train/dev.
- No silent truncation beyond configured policy.

Validation experiment order
---------------------------
1. 1-best T5 smoke run.
2. 5-best T5.
3. 10-best T5.
4. separator/prefix ablation only on development data.
5. three seeds after one configuration is frozen.

Exit gate
---------
- A frozen 10-best T5 checkpoint and validation report.
- All deviations from the paper recorded.

======================================================================
9. MILESTONE M6 - DECODING STRATEGIES
======================================================================

Goal
----
Implement and validate unconstrained, N-best-constrained, and closest decoding.

Tasks: unconstrained
--------------------
- Implement configurable greedy/beam generation.
- Save generation scores and output length.
- Detect empty/truncated outputs.

Tasks: candidate scoring
------------------------
- Implement teacher-forced T5 sequence log probability.
- Return sum, mean, token count, and EOS policy.
- Batch candidate scoring.

Tasks: N-best constrained
-------------------------
- Implement interpolation with ASR score.
- Search lambda 0.00 to 1.00 by 0.05 on validation only.
- Store full WER-vs-lambda curve.
- Implement raw-score main variant and labeled normalization ablations.

Tasks: closest
--------------
- Generate unconstrained output.
- Use word-level Levenshtein for English.
- Deterministic tie-break: EC score, ASR rank, lexical.

Required tests
--------------
- Constrained and closest outputs are always in the N-best list.
- lambda=0 returns ASR-score-best candidate.
- lambda=1 returns EC-score-best candidate.
- teacher-forced score matches a manual fixture.
- closest projection matches a hand-computed example.

Exit gate
---------
- Reproduced Table-II-style result for the available ASR backend.
- Paper result comparison includes baseline mismatch and confidence intervals.

--------------

14. DEBUGGING DECISION TREE
======================================================================

Problem: reproduced baseline WER is too high
1. Verify split and reference text.
2. Verify normalizer revision and ordering.
3. Verify audio sample rate and channel conversion.
4. Verify model/revision/language/task.
5. Verify beam and fallback settings.
6. Inspect segmentation and empty/truncated outputs.
7. Compare a small set with stock model output.

Problem: oracle WER barely improves with N
1. Check that candidates are actual distinct beams, not repeated one-best calls.
2. Check score sorting and N exposure point.
3. Check that segment alternatives are composed correctly.
4. Measure normalized uniqueness.
5. Inspect whether variation is only punctuation/format.
6. Increase beam only as an ablation; do not assume bigger is better.

Problem: T5 worsens WER
1. Confirm training pairs contain useful errors.
2. Inspect input/target truncation.
3. Test tiny-set overfit.
4. Check target normalization consistency.
5. Compare 1-best vs 5-best vs 10-best.
6. Inspect overcorrection and deletion rate.
7. Try constrained decoding before changing training.
8. Only then test separator/prefix and augmentation ablations.

Problem: constrained decoding behaves strangely
1. Verify candidate teacher-forced score.
2. Verify ASR score semantics and order.
3. Plot both score distributions.
4. Check length bias.
5. Check lambda endpoints.
6. Check that raw and normalized text have not been mixed.

Problem: zero-shot output truncates
1. Check max output tokens.
2. Tighten output-only instruction.
3. Use closest projection or option selection.
4. Count invalid outputs; do not silently repair text.
5. Compare deletion rate before claiming improvement.

Problem: reproduced number differs by a few hundredths
1. Run multiple seeds.
2. Bootstrap the paired WER difference.
3. Check checkpoint selection and decoding beam.
4. Do not overfit to the paper's rounded value.

======================================================================
16. AGENT STOP CONDITIONS
======================================================================

Stop and ask for researcher review when:
- the public ASR checkpoint differs materially from the paper architecture;
- the baseline WER cannot be explained;
- the Whisper N-best patch changes top-1 output;
- score semantics are unknown;
- a test split would be used for hyperparameter selection;
- an LLM provider silently aliases the requested model;
- a dataset license or access condition is unclear;
- lattice conversion cannot be proven equivalent on toy graphs;
- an assumption would materially change the scientific claim.

Do not stop merely because exact historical artifacts are unavailable. Implement the
closest transparent method reproduction and document the boundary.
